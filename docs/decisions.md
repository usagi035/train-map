## 1. モジュール化の方式 → **決定: ESM(`<script type="module">`)を採用**

- **確認したこと**: Electron 33・`file://` 読み込みで、`<script type="module">` の静的 import と動的 `import()` の**両方が動作する**ことを検証した(検証用アプリで `ESM_STATIC_OK` / `ESM_DYNAMIC_OK` を確認)。
- 現行の CSP(S2 以降は `default-src 'none'; script-src 'self'; …`)も同一オリジンのモジュールを許可する。
- **選択肢**
  - (A) **ESM を使う** ← 採用。仕様3.2の「`ui` は `online` を `import()` で動的に読み込む」と整合。ファイル分割も自然にできる。
  - (B) グローバルスクリプトを複数分割(順序依存・名前空間オブジェクト) — 実装は簡単だが依存の向きを機械的に守れない。
  - (C) ビルドツール(bundler)を導入 — 仕様13.6「依存は原則追加しない」に反する。
- **注意**: `package.json` の `"type"` は**変更しない**(`main.js` / `scripts/` は CommonJS のまま)。ESM は **renderer 側だけ**で使う。`main.js` を ESM 化する必要はない。

## 2. ID の生成方式 → **決定: (B) `crypto.randomUUID()` に統一**

2026-10-05 確認。**新しく作られる ID だけ**が変わる(既存ファイルに入っている ID・`migrate()` は変更しない)。

| 選択肢 | 利点 | 欠点 |
|---|---|---|
| (A) **既存の `uid()` を維持** | 変更不要。既存ファイルと完全互換。Phase 1 の「動作を変えない」に最も忠実 | `crypto` 非依存(乱数の品質は低いが7文字で衝突は実質無い) |

## 10. 画面側の分割方針(Stage C)→ **決定(2026-10-05 実装・検証済み)**

`docs/core-split-instruction.md` §8〜§12 に沿って `src/ui/renderer.js` を画面モジュールへ分割した。

- **構成**: `src/renderer/` に `ui-state.js`(共通状態・共通操作・`renderAll`)、`canvas.js`、
  `side-panel.js`、`left-panel.js`、`tabs.js`、`renderer.js`(入口・入力配線)。旧 `src/ui/renderer.js` は削除。
- **import の向きは `ui-state → 各画面モジュール` の一方向だけ**(相互 import で循環しない)。
  `renderer.js` は入口として他から import されない。core は画面のどのモジュールからも import できてよい
  (`renderer → core` の一方向は維持、core は DOM/Electron 非依存のまま)。
- **描画の登録**: `renderAll()` は `ui-state.js` に置き、各モジュールの描画関数は `renderer.js` が
  `setRender({tabs, home, canvas, side, left})` で**最初の `renderAll()` より前**に登録する。
  1つだけ描き直す場合は `renderPart(name)`(入力中の欄を作り直さないため)。
- **画面側の小さな共有状態**: 「画像を変更」の差し替え対象は 2つのモジュールで使うため `ui-state.js` の
  `imgPick`(可変オブジェクト)に集約。ESM の import は束縛に代入できないため、可変のものは
  `ui` → `replaceUi(next)`、状態全体 → `replaceState(next)` のように**代入ではなく関数**で渡す。
- **core の生成場所**: `ui-state.js` が生成し、画面側全モジュールがそこから import する
  (`core` を先に作らないと起動時の `importDocument` が動かないため)。
- **検証**: `node --check`(全モジュール)と core スモーク全 ok / ブラウザ回帰 64 項目 + 追加 16 項目合格・
  コンソールエラー 0 件 / Electron(`file://`)で起動・編集・再読込・コンソール問題 0 件。

## 15. 読み込むJSONを必ず検証・修復する(`src/core/sanitize.js`)→ 決定(2026-10-07 実装・検証済み)

依頼: `IMPROVEMENTS.md`(指示書 S1/S1b)。「他人の JSON を開く」のがこのアプリの通常の利用手順で、
公開サイト( GitHub Pages )では読み込んだ中身がそのまま `innerHTML` に流れ込むと保存型 XSS になる。
CSP は `script-src 'unsafe-inline'` のためインラインイベントハンドラを止められなかった(S2 で除去済み)。

- **方針(指示書の硬性規則どおり)**: ①**白名单で新規オブジェクトを作る**(入力は一切書き換えない・スプレッドしない)、

  ③**出口側も縦に防御**(`esc()` に加えて `col()` / `num()` / `idf()` を、データを入れるテンプレートへ。

  攻撃用の文字列が入らないようにする。算術は `num()` で数値にそろえてから掛け、
  **文字列連結になる式(`b.x + b.w / 2`)は必ず先に数値化**する)。
- **入口は3つをすべて同じ関数へ**: 「読み込み」ボタン / 起動時の `railmaps` 読込 / `storage` イベント(タブ間同期)。

  起動時に入れ直せない場合は初期状態で始めるが、**保存文字列はユーザーが編集するまで書き換えない**(データを消さない)。
- **検証内容**: 色は `#rrggbb` のみ、数値は `Number.isFinite`(文字列は数値化せず既定へ)とクランプ、
  ID は `[A-Za-z0-9_-]{1,64}` で一意(作り直したら `links` の参照も追従)、列挙値は許可リスト、
  画像の `src` は `data:image/(png|jpeg|webp|gif);base64,…` のみ(svg・javascript:・http(s)・相対URLは画像ごと削除)、
  件数は `LIMITS` で上限(超過は切り詰めて `warnings`)。白名单は `model.js` / `migration.js` /
  **画面が読むプロパティを grep して**作成(落とせないデータを減らすため)。

## 16. CSP から `script-src 'unsafe-inline'` を外す(`index.html`)→ 決定(2026-10-07 実装・検証済み)

依頼: `IMPROVEMENTS.md`(指示書 S2)。S1/S1b は「不審な文字列をデータ側から弾く」防御であり、
CSP がインライン実行を許している限り、入口が1つでも通ればコード実行まで到達しうる。
`script-src 'unsafe-inline'` を外すことで、仮に属性へ `on*` が入っても発火しない最後の砦にする。

- **採用した CSP(指示書の指定どおり)**:
  `default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; base-uri 'none'; form-action 'none'`
  - `script-src 'self'` = 同一オリジンの外部ファイル(`<script type="module" src>`)のみ。
    インライン `<script>`・インラインイベントハンドラ・`javascript:` URL をすべて拒否
  - `default-src 'none'` = fetch / Worker / webfont / media を全て拒否(**このアプリは未使用**)。
    保存は localStorage、書き出しは `blob:` の `<a download>` なので影響しない
  - `img-src 'self' data:` = 画像は取り込みの data URL と同一オリジンのみ
  - `style-src 'unsafe-inline'` は維持(インライン `<style>` と `style=""` 属性を多用しているため)。
    **残っている緩和点として README の「現在の制限」に明記**
  - `base-uri 'none'` / `form-action 'none'`(`<form>` は無い)
- **掛け方**: `index.html` の `<meta http-equiv>`(GitHub Pages はヘッダを設定できないため)。
  その代わり `frame-ancestors` / `report-uri` は使えない(README の現行制限に明記)。
- **前提の確認**: `src/` での `fetch` / `XMLHttpRequest` / `Worker` / `createObjectURL` の利用は
  `renderer.js` の書き出し2箇所のみ(`blob:` + `<a download>`)。インライン `<script>` は無く
  (`index.html` のエントリは外部モジュール1本)、インラインの `on*=` 属性を生成している箇所も無い。

- **検証(実ブラウザ http://localhost:8080/)**: 変更後にリロード → 通常運用のコンソールエラー0件・
  警告0件・ダイアログ0件、描画(駅5・路線1・画像 data URL 1)は従来どおり。以下3つが**すべて拒否**され
  それぞれ CSP違反としてコンソールに出ることを実測した。
  1. `createElement('script').textContent = '…'` で挿入したインライン script → 実行されない
  2. `setAttribute('onclick', '…')` したボタンをクリック → ハンドラが発火しない
  3. `javascript:` URL をクリック → 実行されない
  通常機能の回帰: ツール切替 / ズーム(125%→100%)/ レイヤー選択(色・太さの入力)/ 駅選択 /
  書き出し(JSON・PNG = `blob:` ダウンロード)/ 路線図一覧の開閉、いずれも動作し違反は出ない。
  自動テストは `test/csp.test.js`(meta が指す方針そのものと、インライン script が無いこと)。

## 19. 自動保存の失敗を「直るまで消さない知らせ」にする(S5)→ 決定(2026-10-07 実装・検証済み)

依頼: `IMPROVEMENTS.md`(指示書 S5)。従来は**1回だけ `alert()` して以後は黙る**方式で、

  - 1回だけの `alert()` と `quotaWarned` は**廃止**(常駐バナーが代替。画面を止めるため)。

- **文書本体の `setItem` 失敗はすべてこの経路へ**: `save()` と `applySnap()` の2か所のみ。
  空の `catch` は消した。**表示だけの設定**(`savePanelW` = 幅、`persistOpen` = 開いているタブ、
  `saveAcc` = 開閉状態)は「文書本体ではない・書けても内容は失われない」ため握りつぶすが、
  **その理由を各所にコメントで明記**(指示書が求めている条件)。
- **旧キー移行の失敗も同じ経路**: `migrateLegacyKeys()` が書き込みに失敗したら false を返し、
  起動時に `setSaveFailed(true)` で最初から知らせる(書けない環境は以降の保存も同じ)。
- **検証(実ブラウザ)**: `Storage.prototype.setItem` を容量超過を投げるように差し替え → 編集後、

  止まる(`dispatchEvent` が false)、`console.warn` に理由、**`alert` は0件**。
  バナーの「書き出し」はクリックでき(JSONを保存)バナーは残る(close:false)。
  書き込みを復旧して編集 → **バナー消え・`beforeunload` 解除・保存成功**を実測。
- **自動テスト**: `test/s5.test.js` 5件(成功時は何も出さない / 失敗でバナー+beforeunload+warn /

## 26. 初回の案内とサンプル、一覧の件数・最終更新・複製・名前変更(U5)→ 決定(2026-10-08 実装・検証済み)

## 27. 画像の書き出し(倍率・背景の透過・選択枠の非表示・SVG・revoke の遅延)(U6)→ 決定(2026-10-08 実装・検証済み)

依頼: `IMPROVEMENTS.md` Part2 U6(PNG export: 1× / 2× / 3×, transparent background, no selection chrome in
exports, SVG export, revoke object URLs after the download starts)。

- **選択の枠は「クローン側だけ」で消す**: 生きているキャンバスから消すと書き出しのたびに画面が
  描き直されてチラつく(指示書も「クローンから消す」ことを明示している)。そのため `renderCanvas()` が
  出す **選択の枠・ハンドル・□の枠とハイライト・道路ツールの描画中プレビューに `data-chrome="1"`、
  背景の四角に `data-bg="1"`** という印を付け、書き出しは `#cv.cloneNode(true)` したクローン側で
  `[data-chrome]` だけを取り除く。書き出し側に `#cv` を書き換える経路は作らない(テストで検査)。
  - **地図の外周の破線枠・グリッド・駅間隔の数字は残す**: どれも選択したものではなく、従来の書き出しにも
    出ている要素。指示書が対象に挙げたのは selection chrome(選択の枠・ハンドル・□の枠)だけなので、
    変わったのは「選択していても写らない」ことだけにする。
- **倍率 1× / 2× / 3× と背景の透過は「画像書き出し」の設定ポップアップ(`#exppop`)で選ぶ**。
  「?」の一覧(`#keyspop`)と同じ形 = 場所を押して開閉、外側を押す / Esc で閉じる、`aria-expanded` を追従。
  既定は **1× かつ背景あり** = 従来の書き出しと同じ結果。`prompt()` もダイアログも使わない(U2 の方針)。
  ラジオは `fieldset`+`legend` で1グループにまとめる(読み上げでも「大きさ」の選択と分かる)。
- **解像度は「マップの大きさ × 倍率」**: SVG が画像として読まれるときの解像度は `width`/`height` で決まる
  ので、クローンの幅/高さをマップ×倍率に、`viewBox` をマップ座標に書き換える。
  **表示中のズームに引きずられない**(ズームを拡大したまま書き出しても、その倍率では伸びない)。
- **透過は2か所**: `#exptrans` が ON ならクローンの背景の四角を外し、canvas にも背景を塗らない

- **SVG 書き出し**: クローンを `XMLSerializer` で直列化して `image/svg+xml` で保存。

  継承しないため、埋めないと単体で開いたときに別の書体になる)。ファイル名は `safeFilename(地図名).svg`。
  背景の四角も透過チェックで外す = SVG も「背景あり / 透過」を選べる。
- **revoke は必ず遅らせる**: `a.click()` の直後に `revokeObjectURL()` すると、ダウンロードが走り始める前に

## 18. 別タブからの上書きを止め、どちらを使うか選ばせる(S4)→ 決定(2026-10-07 実装・検証済み)

依頼: `IMPROVEMENTS.md`(指示書 S4)。`storage` ハンドラはドラッグ中しか見ていず、入力中でも文書を
入れ替えていたため、打かけの入力や未保存の編集が相手の保存で**無言で消える**ことがあった。

- **方針**: 「こちらに未確定の作業がある間は適用しない」+「非ブロッキングなバナーで選ばせる」。
  `alert()` / `confirm()` は画面を止めるので使わない(指示書 U2 と同じ方針)。
- **作業中の定義**(`ui-state.js` の `shouldAskRemote(busy)` に集約): 自動保存の保留(`saveTimer`)・
  **入力欄にフォーカス**(テキスト系)・ドラッグ中・道路描画中、および「自分の版を残す」を選んでから
  次の保存が成功するまで。競合が決着していない間は、新しく届いた相手の版でも自動適用しない
  (バナーの中身だけ最新へ入れ替える)。
- **バナー**(`src/renderer/banner.js`): 名前ごとに1枚、`role="status"` + `aria-live="polite"`、
  文字は `textContent`、ボタンは `addEventListener`(CSP でインラインが弾かれるため)。
  選択肢は「相手の版を読み込む」= サニタイズ経由で適用+履歴リセット、
  「自分の版を残す」= 次の自分の保存が成功するまで相手の版を受け取らない。
  JSON を読み込んで文書を入れ替えたときは、保留中の相手の版を捨てる。
- **決定した見送り**: `BroadcastChannel` は使わない。`storage` イベントで全タブに届くため機能的な差が
  無く、経路が2本になると検証と修正が二重になる(項12-3 で見送った方針を継続)。
- **検証(実ブラウザ・2タブ http://localhost:8080/)**:
  ①A で駅名を入力中(フィールドを離れない)に B が路線図を追加 → **A は上書きされない**
  (state 1件のまま・入力値そのまま)、2ボタンのバナーが出る。
  ②「自分の版を残す」→ バナー消え・`isLocalAuthority()` true、B が再度書き換えても
  **黙って適用せずバナーが再表示**される。
  ③「相手の版を読み込む」→ A が相手の版(3件)へ切り替わり履歴リセット(`canUndo()` false)。
  ④A が idle なら従来どおり**バナーなしで自動適用**(3→4件)。両タブともエラー0・ダイアログ0。
- **自動テスト**: `test/s4.test.js` 6件(バナーの実挙動を最小DOMスタブで実測 / 判定ロジックの実測 /
  画面側の配線のソース検査)。全体で 34/34 green。
